# Reviewed agent conversations

## Boundaries
- Only reviewed convergence supplies an occurrence and workflow to the continuity port. Router-selected profile and effective workspace policy are host inputs. A fresh dispatch without retention invalidates a prior exact-key slot; a different role or producing step cannot. The PR binding is separate from the scope digest.
- Slot admission requires both SQLite workspace generation and a host proof of the run directory, repo and scratch instances, linked worktree, and (in server composition) owning Git repository. A same-path replacement or explicit start-over fences prior completions. Do not infer handles from checkpoints, tool output, Sessions, or scratch.
- The runner hands native IDs back privately. Publish a handle only after current completion, result acceptance, attempt recording, and ownership recheck. Slot publication failure does not replace an otherwise accepted result.
- Scope custody is separate from workspace enrollment. The marker is host data outside the declared roots. Reclamation must not use PID absence as exit evidence. The existing guarded pruner leaves unknown writers untouched, including orphaned pre-handle scopes. Do not point `CODEX_HOME` or Claude config at a scope and call that confinement.
- Production reviewed dispatch and `pr.finalize` share the fresh-session resolver. For either built-in Claude auth path, match the SDK version, CLI version, OS, architecture and auth path against the independent release list before setting `persistSession: false`.
- `pr.finalize` never takes a slot or a handoff. Read the integrated commit copy and pinned diff under an attempt-specific scratch directory. Symlinks and gitlinks are described rather than followed. A result from a previous occurrence does not establish an attestation or a valid freeze.

## Proposed tool isolation

Disposable permission tests on macOS arm64 showed that the pinned Codex App Server named permission profile could deny a synthetic history directory without revoking workspace reads for either role. Claude's built-in file denies and enforced Bash sandbox denied the same kind of probe. The adapters now apply these boundaries to protected fresh turns as well as retained turns. Dedicated provider sign-in homes are never inherited by fresh fallback or publication review. The control-plane launcher changes only the leased history paths; it never creates or copies sign-in credentials.

## Host launch and restart verification

Use only an execution host with an existing supervisor that can isolate a native writer and **all** descendants, and preserve evidence independently of the control plane. Without that service, keep retention disabled. Configure `AUTOCATALYST_NATIVE_HISTORY_SUPERVISOR` as a canonical absolute path to its trusted executable bridge and `AUTOCATALYST_CODEX_BUSINESS_HISTORY_HOME` and/or `AUTOCATALYST_CLAUDE_SUBSCRIPTION_HISTORY_HOME` as separate canonical, owner-only homes outside the workspaces. Sign in through the vendor binaries while no service or other writer is active; do not point fresh login, an interactive client, or another service at these homes. The native lease will not replace an ordinary history directory. Do not delete an unverified marker or follow a history link by hand.

The bridge interface is `autocatalyst.native-history.v1`. The control plane runs it directly, not through a shell. It accepts:

| Invocation | Required host behavior |
| --- | --- |
| `describe PROVIDER HOME` | Return JSON with `protocol`, `provider`, `home`, canonical native `executable`, `version` (`0.171.0` or `subscription:0.3.177:2.1.328`), executable `sha256`, exact `confinement` identity, `historyToolIsolation: "all_launches"`, opaque `accountBinding`, `credentialRevision`, `storageNamespace`, and Codex `accountEmail`. Verify current first-party sign-in, account/organization, host policy and binary, rather than reading an unchecked configuration echo. Credential/account changes must change the binding or revision. Return no tokens. |
| `reserve WRITER GROUP TENANT RUN GENERATION` | Reserve this exact tuple durably for a single supervised launch. Return JSON with `protocol`, `writerIdentity`, `descendantGroup`, `tenant`, `runId`, `generation`, and `state: "reserved"`. |
| `run WRITER GROUP TENANT RUN GENERATION PROVIDER HOME SCOPE EXECUTABLE SHA256 CONFINEMENT ACCOUNT REVISION NAMESPACE -- ARGS...` | Verify the live reservation, home and scope ownership, binary, current account/binding/revision and confinement again. Launch the actual native process inside the supervised group exactly once, before it can fork or persist. Pass stdio to the native process without injecting bridge diagnostics into its protocol. Track it and descendants through EOF, signals, client disconnect, and control-plane crashes. Enforce that no agent tool or other writer can get at history, including via aliases, other provider homes, inherited subprocess metadata, or peer run roots. A tool sandbox that tests only the launching run's path does not qualify. |
| `seal WRITER GROUP TENANT RUN GENERATION` | Prevent future launch for this reservation; confirm the native writer and descendants really exited or that a known reservation was sealed without launching. Only then return the same tuple with `state: "sealed_and_exited"`. |
| `exited WRITER GROUP TENANT RUN GENERATION` | Read the durable sealed exit receipt, with the same fields as `seal`. Never mint a receipt for an unknown writer or on PID disappearance. If unavailable, return failure and leave the lease untouched. |

Use the host supervisor's inspection/termination mechanism to resolve an interrupted reservation. Restart recovery and guarded workspace reclamation use the same evidence; an unknown writer blocks only affected custody. Another run contending for the same dedicated home must go fresh until that lease is safe to release. A different home does not have to wait. Retain the bridge and its receipts while old scopes can still exist.

## Docker-free macOS probes

A disposable launchd job stopped an ordinary synthetic child when the parent exited. A child that started its own session survived the parent and wrote a marker before exiting. The native sandbox could deny all forks, but the tested process-information restrictions still allowed the child to start a new session. A launchd job or a POSIX process group alone cannot satisfy the current descendant-exit requirement while preserving provider tool execution.

A separate live test used the same signed-in provider builds and a unique synthetic marker. Codex kept an ephemeral App Server thread alive for two turns. Claude kept a streaming SDK query alive with `persistSession: false` and sent two turns. Both returned the exact first-turn marker on the second turn, and the tests found no newly saved transcript. This supports an in-memory continuity design that starts fresh after a server restart. PR #206 uses this mode by default for the verified Claude subscription build and pinned Codex sign-in adapters on reviewed work. It keeps one accepted conversation per tenant, run, step, and role, with worktree, route, account, tool and CI repair PR compatibility checks. The service holds up to 16 resources and evicts the least-recently accepted idle one under pressure; an all-active pool declines admission. Idle leases last up to 48 hours with a 15-minute workspace check. Terminal transitions (including cancel), workspace rematerialization/reset, failed proof, and shutdown retire leases. Late callbacks cannot reinstall a retired resource. Missing or incompatible context receives the ordinary fresh handoff, as does the first turn after restart. PR final review uses a fresh connection. The native on-disk release list remains empty.

### Session reuse across rounds and CI repair (#212)

- The first spec author can claim provisionally. The spec engine settles the lease only after it accepts the expected kind/path and exact dispositions, stages the candidate, and checkpoints it. The path joins the compatibility check at that point, not at provider schema validation. Rejected candidates start over cold.
- Build compatibility keeps the PR identity separate from the generation/role/route/tool-policy key. The repair worker provides the exact repository, branch, PR ID and number after verifying the open PR/head, local candidate and repair ownership. Each role can adopt that binding once; subsequent reuse requires the same binding. Final review stays fresh.
- Query `reviewed_conversation_reuse` by attempt ID. `resume_selected` is intent; `resume_submitted` means the adapter crossed the prompt submission boundary, not a verified response. A refusal carries a fixed reason (e.g. `workspace_unverified`, `transport_closed`, `transport_error`, `pre_submit_timeout`, `account_changed`, `launch_changed`); the fresh attempt points back via `fallbackFrom`. The opaque conversation ID comes from the host, not the provider. A proven pre-submit refusal does not create a Session. Evidence is operational only and never authorizes a publication.
- Claude live turns are resumed for usage accounting. The query retains request/message IDs privately to filter replay, and resumed turns ignore terminal aggregates; without owned counts the usage is unavailable, otherwise partial. No native IDs leave the query. Close rather than truncate the identity history.
- The control-plane wire fixture (`src/integration.spec.ts -t "production reviewed Codex reuse"`) exercises real two-root provisioning, two spec/build rounds, actual idle subprocess close and fallback, and first CI repair on the same local, simulated PR. It checks that final review is fresh on both publication attempts. The build reviewer uses a fixture adapter: Codex with a strict Read/Glob/Grep build-review policy still fails closed rather than gaining a shell. The pool unit tests advance 14 hours on a controlled clock and cover exhaustion, retirement and later exact-PR matches.

The opt-in `reviewed-live-conversations.live.spec.ts` uses the production reviewed port, a real worktree and SQLite, and the actual provider transports. It covers repeated spec/build roles, a fixture-bound repair and cold final review across occurrences. Set `AUTOCATALYST_LIVE_MEMORY_PROVIDER` (`claude` or `codex`), `AUTOCATALYST_LIVE_MEMORY_MODEL`, and an independently signed-in `CLAUDE_CONFIG_DIR` or `CODEX_HOME`. Run `pnpm nx test control-plane --skip-nx-cache -- reviewed-live-conversations.live.spec.ts` on the authorized fixture host. This is an adapter/port smoke, not a remote CI or service acceptance test.
