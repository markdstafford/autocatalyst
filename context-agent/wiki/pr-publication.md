# PR publication and CI repair (#201)

- **Initial publication:** `pr.finalize` integrates the project target (`main`), reviews read-only, and records a host attestation of the reviewed and publishable SHAs. A spec freeze can add only the generated frontmatter change; a complete spec is a no-op. Do not use `provisionedBaseRef` for publication. `pr.open` guards the attestation and target before the push and again before create. No Git merge happens in `pr.open`. The first two invalidations create fresh `pr.finalize` occurrences; the third stops at `pr.open`. A failed verification spends no refresh. For the named host checkpoint/step pairs, Resume reuses the branch and starts a new publication epoch.
- **Provenance:** Migration 0012 does not backfill. The host writes a run/repo/branch/full-SHA receipt after a verified push, before create. Exact adoption can recover an already-effective create even after target drift. Advancing onto the PR gate persists the marker with the run transition. Do not derive a marker from authorship, provider head, a pre-upgrade checkpoint or bare push intent.
- **Observation:** `pr-lifecycle.ts` shares provider identity and terminal reconciliation. Only authorized batch calls (including the opt-in tenant-scoped ticker through that service) allow CI admission. Targeted refresh and regular ticks do not admit. GitHub observes exact-head GraphQL check runs and legacy statuses, using PR-scoped requiredness; malformed/partial results or a changed binding are unknown. The tenant cursor rotates bounded 50-PR/30-second passes.
- **Repair:** `pr_ci_repair_heads` keys decisions by PR and failed head; active-slot/ordinal uniqueness and immediate SQLite transactions cover admission, claim, guidance, publication intent/attestation, receipt and outcomes. The original gate is immutable. A finished nonterminal attempt closes its current step and opens exactly one new PR gate. Terminal outcomes supersede without another gate. A reclaimed process epoch never launches already-claimed work or blindly resends a push. The same run/PR/branch is used, docs/gate steps are bypassed, and the integrated candidate tree must differ from the failed tree.
- **Activity:** `GET /v1/runs/:id/steps` projects typed, occurrence-keyed entries and current coverage. Public evidence excludes raw job logs, Git output and absolute workspace paths. `pr_ci_activity` uses the existing checkpoint SSE type as a refetch hint. Durable rows and checkpoints are authoritative on reload. A held workspace cannot be reused through recovery/dispatch; verification and salvage need an authorized operator.
- **Configuration:** The periodic ticker remains off unless explicitly enabled with one configured and authorized tenant and interval. `AUTOCATALYST_PR_CI_REPAIR_LIMIT` defaults to 2; accepts nonnegative safe integers; zero disables admissions, not terminal observation. A committed decision keeps its original cap. A local/fake deployment keeps its existing start-up behavior. No dispatcher-wide lock was added.
- **Guard details:** Integration protects ignored files from overwrite. An updated remote ref plus Git's porcelain update acknowledgment establishes initial host push evidence; an up-to-date report does not. Before creating the PR, recheck the pushed source as well as the target and local candidate. The rendered changed paths come from the exact pinned diff.
- **Guidance:** Dispatch wakeups deduplicate by queued occurrence, not by run, so an immediate exact-pause guidance reply cannot be lost while the previous dispatch drains. Implementer questions checkpoint changes before parking; the same web guidance form is reused for repair and spec questions. Repair guidance remains in Activity after the reply.
- **Startup:** Skip workspace materialization for held or active repair runs. Claim recovery starts without blocking server readiness on provider I/O; the active SQLite row fences that PR until recovery finishes.
- **Tests:** `apps/control-plane/src/publication-git.spec.ts` uses real local Git for integration, post-push conflict, same-PR repairs, review stops, and restart guidance through the orchestrator and migrated SQLite. `packages/core/src/pr-repair-worker.spec.ts` checks recovery of a retired publish claim. `packages/persistence/src/__tests__/pr-ci-repair-repository.spec.ts` uses two connections to cover claims, continuation, intent and holds. `packages/github-code-host-adapter/src/github-required-checks.spec.ts` exercises provider pages, supersession and independent terminal reads. Run individual Vitest projects with their checked-in Vite config (for example `cd apps/control-plane && pnpm exec vitest run src/publication-git.spec.ts`).
- **Human-owned contracts:** Hand the unapplied `../proposed-human-docs/issue-201-pr-publication-and-ci-repair.patch` to `docs.update` as input for `docs.human_review`. Do not apply it in a repair.
